## Start a static package

Extract a complete Web package and serve its folder over HTTP. If Python 3 is installed, run this inside the folder containing `index.html`:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Open `http://127.0.0.1:8080` in a supported browser. Direct `file://` opening does not reliably load WebAssembly. A complete shared-engine package includes `pkg/veycut_web.js` and its Wasm binary, generated by the server workflow. Serving a source checkout without that package leaves the disclosed JavaScript fallback; advanced controls require the shared engine.

Media is selected locally and remains on the device. The current editor makes no media uploads and connects no external model service. Playback and real-time recording use the user's browser and hardware.

## Current development controls

- Import browser-decodable video, audio and images. Arrange mixed tracks, set track visibility/mute, select groups and adjust timeline placement. Trim, split, ripple-delete, copy/paste and duplicate use shared commands with Undo/Redo in Wasm mode.
- Reuse connected files from the media library without importing another copy. The preferred track is used when it has room; placing at the playhead chooses a free track if necessary to preserve exact placement. Appending goes to the preferred track at the end. Saved projects retain source metadata; reconnecting an offline source makes it reusable again.
- Change constant speed or apply a three-point speed ramp (start, middle, end) through the shared project engine. The browser integrates the ramp for seeking and adjusts media playback rate during preview and real-time output. Imported projects can retain more curve points; applying the UI ramp replaces them with three. Clear a ramp before trimming or splitting because those native edit operations do not preserve its nonlinear source map. Change volume, audio fades and mute. Bass, treble, telephone and one-repeat echo controls run in both browser preview and recorded output through Web Audio. Their response, timing and limiter approximate the native FFmpeg chains; other native audio filters remain unsupported for browser export. Set position, scale, rotation, opacity and crop. Add property keyframes; the browser compositor interpolates supported properties.
- Add titles and caption text as native **shared-engine text clips**. Here, native means stored in the shared project document; browser Canvas draws the text using available browser fonts. Font shaping, colour and layout can differ from the Mac renderer.
- Create square, circle, triangle, parallelogram, trapezoid, line and arrow layers with size, fill, outline and duration controls. These shared-engine clips need no media file; placement, transforms, property keys and picture effects use the existing inspector. Paint is chosen when creating a shape. Native shape geometry is reproduced in Canvas, with browser antialiasing differences.
- Import the supported UTF-8 SRT or plain-text WebVTT subset; edit cue text, timing, size, colour and background; add/delete cues and use literal find/replace. Download SRT or WebVTT. Atomic import uses one stable caption lane and one Undo, bounded by **512 total project clips**, a **1 MiB serialized request**, and non-overlapping cue times. Group property edits remain bounded to **32 commands**. Files are at most **1 MiB**. The simple browser parser does not provide every native WebVTT feature.
- Add, rename, select and remove timelines; each timeline retains its subtitle-role map and frame/rate settings. Selection does not consume Undo. Frame buttons and Home/End/arrow keys navigate the timeline; Shift plus an arrow steps ten frames. Keyboard shortcuts leave focused editing fields alone. Stereo meters show live RMS levels and a held peak.
- Preview mixed video/image/text layers through the shared browser compositor and mix active source audio. Export uses that compositor and audio-gain logic. Browser preview and output timing remain device-dependent.

Thirteen supported picture effects are **exposure, contrast, saturation, warm, cool, vibrance, posterize, pixelate, sharpen, Gaussian blur, chroma key, mono without grain, and vignette**. Chroma key exposes the screen colour, similarity, softness and spill controls, and its transparency composites over lower tracks in preview/export. Browser blur requires Canvas filter support and uses a different kernel/edge treatment from the native renderer. The other spatial/key effects use SDR Canvas pixels and can also differ slightly from native GPU sampling. Four transition identifiers cover **cross-fade/dissolve and dips through black/white**; shared preview/export resolves source-handle preroll or a frozen silent first-frame hold without changing the saved native edit. Supported browser treatments cover a subset of the native property/effect model. Most native audio filters, HDR pipeline, model/transcription tools, automatic cutout and reverse are not at parity. Unsupported enabled treatments are rejected for export rather than silently promised as rendered.

The inspector lists every effect on the selected clip, including unsupported treatments retained from imported projects. You can open supported settings, enable or disable an effect, move it in the stack and remove it; each stack change is undoable.

## Project save and reconnect

Save downloads a browser JSON envelope containing edits, source filename/size metadata and, in Wasm mode, the shared `engineDocument`. Media bytes are not embedded. Reopen the JSON, then reconnect original files before playback/export. Reconnection checks saved filename, size, kind and needed source ranges; these checks do not establish a cryptographic match.

Open a supported desktop JSON manifest directly. Its original paths, all timelines and native properties are checked for preservation before the live session is replaced; lossy or unsupported document conversions are refused. Media selection checks filename, kind, declared dimensions and source ranges across all timelines. Native manifests do not carry a file byte size: the first reconnection pins the chosen size and is not a cryptographic identity check. **Save desktop JSON** downloads a manifest backup with original paths, not a complete runnable project folder or media/font bundle; browser-added media paths are refused. Back up the original desktop project folder before restoring the JSON under its original manifest filename. Native manifests do not distinguish subtitle roles, so imported text clips are initially listed as captions; Web envelopes retain explicit roles across timelines. Loading a JavaScript-only project retains fallback mode and its narrower feature set. Current frontend JSON input is bounded to **4 MiB**; the bridge separately bounds native documents to **8 MiB**, ordinary command requests to **64 KiB**, bulk-caption requests to **1 MiB**, and projects to **128 media items, 512 clips, 64 tracks and 8 timelines**. These are ceilings, not performance guarantees. Local probes measure dimensions/duration; video frame rate and audio-stream presence are not independently measured as native metadata. Decoded source audio can still be played and recorded.

## Real-time export in development

Current limits are **600 seconds (ten minutes)**, **1920-pixel long edge**, **256 MiB of recorded output**, and **16 simultaneous decoded media layers**. The preview also bounds needed active/selected media sources to 16. The server workflow includes an optional five-minute source/reopen/cancel/export scenario with timed colour and audio markers and a late Persian caption. A separate real-footage scenario imports a long 1080p live-action/CGI film and checks a six-minute 640×360 H.264/Opus MP4. Ten-minute output, higher-resolution/many-layer performance, other camera codecs and the byte ceiling still need stress tests.

Export uses browser Canvas capture, MediaRecorder and Web Audio. Select WebM, or **H.264 MP4 only when the browser explicitly reports codec support** (AAC preferred, Opus fallback shown in the interface). Unsupported formats are disabled; MP4 is not a bundled offline H.264 encoder or a promise of universal browser support. Available codecs follow MediaRecorder support. Requested output frame rates are 24, 25, 30 or 60 fps; delivered frame timing can drift.

The compositor draws aspect-fitted media, transforms, supported effects and text over black. Timeline gaps produce black/silence. Audio sources mix with mute, volume and fades into the recording destination. The real initial frame is prepared before recording. Image painting is paced to the selected output rate, with manual canvas capture where supported; an automatic-capture fallback remains. Caption and shape changes stay inside the active recording segment, avoiding decoder pause/resume cycles at every cue. Keep the tab visible; hiding it aborts recording. A suspended audio clock, a rendering gap above 350 ms, decoding stalls or excessive source drift cancel output. Preparation pauses are excluded from recording where possible; accumulated recorded-time error above 500 ms also refuses output. The UI locks project changes during export. Cancel returns no download and tears down sources, capture tracks and the audio context.

Before download, recording resources are released and the resulting file is opened in a fresh decoder. Dimensions and duration must match, and beginning/middle/end frames must decode. A clip shorter than three output frames uses one decoded checkpoint. Browsers with video-frame callbacks also verify the decoded frame timestamps; this support is required for exports longer than two minutes. This is a checkpoint check, not full frame-by-frame or audio-content validation. The server separately fully decodes the generated fixtures. Missing duration metadata in recorder-produced WebM is added by reading at most 64 KiB of headers and retaining compressed payload as Blob slices. Unsupported indexed/header layouts are refused rather than rewritten incorrectly. MP4 remains conditional on browser H.264 recording support. Opus-audio MP4 may not play in AAC-only applications.

This is an SDR Canvas/real-time recording path. Native half-float HDR compositing, exact native font rendering and frame-accurate offline export are outside its current scope. Decode the whole output and check audio, timing and text before using it.

# VeyCut Web editor

**Expanded Web editor: server-validated source, app version 0.3.1.** This working tree expands the browser editor with mixed media tracks, shared-engine text clips, grouped edits, keyframes and composited preview/export. The public [0.3.1-beta.2 Web ZIP](https://github.com/alirezap73/veycut/releases/download/v0.3.1-beta.2/VeyCut-0.3.1-beta.2-web.zip) contains the earlier single-track prototype. New controls and larger output limits below are not claims about that download.

App version remains **0.3.1**. A hosted editor URL is pending. [Platform support](https://github.com/alirezap73/veycut/blob/main/docs/PLATFORMS.md) separates released and development capabilities.

## Start a static package

Extract a complete Web package and serve its folder over HTTP. If Python 3 is installed, run this inside the folder containing `index.html`:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Open `http://127.0.0.1:8080` in a supported browser. Direct `file://` opening does not reliably load WebAssembly. A complete shared-engine package includes `pkg/veycut_web.js` and its Wasm binary, generated by the server workflow. Serving a source checkout without that package leaves the disclosed JavaScript fallback; advanced controls require the shared engine.

Media is selected locally and remains on the device. The current editor makes no media uploads and connects no external model service. Playback and real-time recording use the user's browser and hardware.

## Current development controls

- Import browser-decodable video, audio and images. Arrange mixed tracks, set track visibility/mute, select groups and adjust timeline placement. Trim, split, ripple-delete, copy/paste and duplicate use shared commands with Undo/Redo in Wasm mode.
- Change speed, volume, audio fades and mute. Set position, scale, rotation, opacity and crop. Add property keyframes; the browser compositor interpolates supported properties.
- Add titles and caption text as native **shared-engine text clips**. Here, native means stored in the shared project document; browser Canvas draws the text using available browser fonts. Font shaping, colour and layout can differ from the Mac renderer.
- Import the supported UTF-8 SRT or plain-text WebVTT subset; edit cue text, timing, size, colour and background; add/delete cues and use literal find/replace. Download SRT or WebVTT. Current atomic import is bounded to **31 cues per file**, and group property edits to **32 commands**. Files are at most **1 MiB**. The simple browser parser does not provide every native WebVTT feature.
- Preview mixed video/image/text layers through the shared browser compositor and mix active source audio. Export uses that compositor and audio-gain logic. Browser preview and output timing remain device-dependent.

The three implemented picture effects are **exposure, contrast and saturation**. Supported browser treatments cover a subset of the native property/effect model. The full native effect catalogue, transitions, HDR pipeline, model/transcription tools, cutout, reverse and variable speed curves are not at parity. Unsupported enabled treatments are rejected for export rather than silently promised as rendered.

## Project save and reconnect

Save downloads a browser JSON envelope containing edits, source filename/size metadata and, in Wasm mode, the shared `engineDocument`. Media bytes are not embedded. Reopen the JSON, then reconnect original files before playback/export. Reconnection checks saved filename, size, kind and needed source ranges; these checks do not establish a cryptographic match.

Direct desktop project import is not implemented. Loading a JavaScript-only project retains fallback mode and its narrower feature set. Current frontend JSON input is bounded to **4 MiB**; the bridge separately bounds native documents to **8 MiB**, requests to **64 KiB**, and projects to **128 media items, 512 clips, 64 tracks and 8 timelines**. These are ceilings, not performance guarantees. Local probes measure dimensions/duration; video frame rate and audio-stream presence are not independently measured as native metadata. Decoded source audio can still be played and recorded.

## Real-time export in development

Current limits are **120 seconds**, **1920-pixel long edge**, **256 MiB of recorded output**, and **16 simultaneous non-text media layers**. The preview also bounds needed active/selected media sources to 16. The short 360×640 scenario passed CI; higher-resolution/many-layer performance and the byte ceiling are not stress-tested. They do not guarantee smooth performance at every supported size or layer count.

Export uses browser Canvas capture, MediaRecorder and Web Audio. Select WebM, or **H.264/AAC MP4 only when the browser explicitly reports support for those codecs**. Unsupported formats are disabled; MP4 is not a bundled offline H.264 encoder or a promise of universal browser support. Available codecs follow MediaRecorder support. Requested output frame rates are 24, 25, 30 or 60 fps; delivered frame timing can drift.

The compositor draws aspect-fitted media, transforms, supported effects and text over black. Timeline gaps produce black/silence. Audio sources mix with mute, volume and fades into the recording destination. Keep the tab visible; hiding it aborts recording. Preparation pauses are excluded from recording where possible. The UI locks project changes during export. Cancel returns no download and tears down recording sources/tracks/audio context; success downloads the browser's recorded WebM or MP4 file.

This is an SDR Canvas/real-time recording path. Native half-float HDR compositing, exact native font rendering and frame-accurate offline export are outside its current scope. Decode the whole output and check audio, timing and text before using it.

## Released beta.2 evidence

The shipped Web prototype has **120-second / 960-pixel / 64-MiB** limits, sequential single-track editing, SRT captions and WebM export. Its earlier [shared-engine/browser check](https://github.com/alirezap73/veycut/actions/runs/38126752421) passed on `d5b813370e5dd86b0addac17f684487461ee0f6c`.

[Export validation](https://github.com/alirezap73/veycut/actions/runs/38137325706) passed on `8c21b937675745375bf72e7e310ab5d4ec4cdb00`. Chromium checked 15 scenarios, including cancellation, disconnected-source refusal, project preservation and a 121-second timeline rejection. A short 360×640 VP8/Opus output fully decoded with source audio and burned Persian/English captions. Those generated-fixture checks apply to the recorded revisions and do not validate the expanded working tree.

The [expanded editing checks](https://github.com/alirezap73/veycut/actions/runs/38192514807) passed on `c538f3f6a8fa0606ae127cacba866de307bfe22a`: eight shared-engine tests, arithmetic/refusal regressions, 16 baseline browser checks, 12 mixed-media editing/export checks and four legacy-project checks. The mixed 360×640 VP8/Opus WebM fully decoded with 64 video frames, a final video timestamp of 2.078 seconds, separate 880 Hz audio, a transformed/keyframed still and native title text. Cancellation, disconnected-media refusal, preserved projects and a rejected 121-second timeline remained covered. MP4 was correctly unavailable on the tested Chromium recorder because explicit H.264/AAC recording was not supported; that path is not a passed MP4 proof.

Safari/Firefox, longer real footage, high-resolution/many-layer performance and the enlarged byte cap remain unverified. All builds, browser runs and video decoding ran on GitHub; no local browser, video recording or native build was run.

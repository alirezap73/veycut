# VeyCut Web prototype

Open `index.html` in a modern browser, or serve this directory as static files. No package install, build, CDN, external service or network media upload is required. When the server builds `pkg/veycut_web.js` and its Wasm binary, the prototype loads the actual shared Rust editing engine. The badge exposes `data-engine="wasm"` only after module initialization and project creation succeed. Import, trim, split, remove and Undo/Redo use shared commands/history; saved JSON includes the real `engineDocument`. Without that package, a disclosed functional JavaScript fallback remains available. Neither mode claims native feature parity.

Import local browser-decodable video, select a timeline clip, seek using the native video controls, trim source in/out points, split, remove, Undo/Redo and preview consecutive clips. Save project JSON to download the edit description. Open it later and reconnect each selected offline clip using the original filename/size. Media itself is never embedded in JSON. SRT files must be UTF-8, at most 1 MiB, with standard `HH:MM:SS,mmm --> HH:MM:SS,mmm` timings; preview overlapping cues, edit text and export SRT. Import replaces the caption set in one undoable edit. English/Persian UI uses the language selector.

Project JSON, SRT and bounded real-time WebM video export are implemented. There is no MP4 rendering, waveform, effects, transitions, multi-source audio mixing or model integration. The sequential single-track preview follows native browser playback and may have gaps at clip changes; it is not a frame-accurate compositor. Subtitle times stay fixed in global timeline seconds when video clips change. Codec support depends on the browser. The local probe measures duration and video dimensions only; source frame rate and audio-stream presence are unknown and are not supplied as measured metadata to the shared engine. Its required audio boolean is supplied as false to represent unprobed metadata; native browser preview can still play audio from the file. Shared trimming can leave a leading timeline gap, which the timeline clock retains; the sequential preview does not render black gap frames. Imported file URLs last only for this page session. Undo history is bounded to 100 edits; JavaScript fallback clip/media count to 2000 (the shared bridge caps 128 media items and 512 clips), caption count to 5000, JSON input to 2 MiB and source duration to 24 hours. The portable browser envelope includes media-reconnection metadata and, in Wasm mode, a native engine document. Opening a JavaScript-only envelope retains fallback mode. Captions currently use the browser subtitle layer; they are not added to the shared engine document. Direct desktop project import is not implemented.

Server validation passed on the exact implementation commit `d5b813370e5dd86b0addac17f684487461ee0f6c`: [VeyCut Web checks](https://github.com/alirezap73/veycut/actions/runs/38126752421). It built the real Wasm package, passed four shared-engine tests and checked Chromium video import, trim/split, Undo/Redo, bilingual SRT editing/download, project save/reopen/media reconnection, malformed-project preservation and Persian mobile layout. The final JSON report, saved frontend/native clip ranges and decoded-preview screenshots were reviewed. The run provides `VeyCut-web-prototype` as a static artifact; it is not a hosted deployment or an official web beta. No local browser/server/build testing was performed.

Remaining validation includes Safari/Firefox, other operating systems, longer real footage, consecutive playback and keyboard focus, unsupported codecs, media mismatch rejection, oversized inputs and object URL cleanup. Runtime performance has not been measured.

## Real-time WebM export

Export uses `Canvas.captureStream(30)` plus `MediaRecorder` (prefers browser-supported VP8/Opus WebM), and one per-export `AudioContext`/video source connected only to a `MediaStreamDestination`, never to speakers. It records actual decoded source audio, independent of the engine’s unprobed audio metadata flag. No microphone permission or upload is used. Aspect-fit video is drawn over black; leading/internal timeline gaps record black and silence, and editable UTF-8 subtitle text is burned using browser canvas fonts. At most the last eight wrapped caption lines are visible per frame, including overlapping cues; longer text is truncated visually but remains intact in project/SRT export. This is not native FFmpeg or frame-accurate offline rendering.

Visible limits: 120 seconds, long edge at most 960 pixels, requested 30 fps, output at most 64 MiB. The recorder pauses for source loading/seeking so preparation waits are excluded. New sources load metadata, prime actual playback while recording is paused, then seek to their saved in point and require an available decoded frame. Preparation failures report the exact awaited event and internal media ready/network/time/error state; they do not substitute an empty frame. Output timing/frames can drift with decoder/device load; WebM duration metadata may be absent, so verify decoded timestamps and full output. Real-time export uses the browser/device for roughly the timeline duration; keep the tab visible (hiding aborts). Reconnect every source before exporting. Project mutations and native preview controls are locked until completion/cancellation. Cancellation returns no download and stops recorder/tracks/video/audio context; successful export is `VeyCut-video.webm`. Unsupported capture/audio/recording APIs disable export, without a substitute fake format.

This new export path has only syntax/static review so far; the earlier passing browser run above predates it. GitHub browser/media decode, audio timing, captions, leading gaps, split segments, missing-source and cancellation checks are required before calling video export validated. No local browser/render/build was run. API design follows [canvas captureStream](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/captureStream), [MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder), [createMediaElementSource](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/createMediaElementSource) and [createMediaStreamDestination](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/createMediaStreamDestination).
